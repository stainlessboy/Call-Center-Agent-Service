# Handoff: Asakabank AI-ассистент — Telegram Mini App

## Overview
Перенос действующего Telegram-бота банка (aiogram + LangGraph-агент на GPT-4o-mini + FastAPI + PostgreSQL) в Telegram Mini App. Чат с AI остаётся ядром продукта, а всё, что сегодня собрано из reply-клавиатур и текста в сообщениях, становится полноценными экранами: каталог продуктов, дерево квалификации, калькулятор с графиком погашения, заявка (лид), отделения, курсы валют, передача живому оператору, настройки.

Аудитория: розничные клиенты в Узбекистане, массовый сегмент, средне-бюджетные телефоны, нестабильный интернет. Три языка: ru (основной), uz, en. Валюта — UZS, суммы крупные, разряды обязательны.

## About the Design Files
Файлы в этом бандле — **дизайн-референс, сделанный в HTML**. Это прототип, показывающий внешний вид, структуру и поведение, а **не production-код для копирования**.

Задача: **воссоздать эти экраны в целевой кодовой базе** (React + `@telegram-apps/sdk`, Vue, Svelte и т.п.) её собственными паттернами, библиотеками и системой состояний. Если фронтенда ещё нет — выбрать стек самостоятельно; рекомендуемый для Telegram Mini App: **React + TypeScript + Vite + @telegram-apps/sdk-react**, стилизация любая (CSS Modules / Tailwind), обязательное условие — все цвета через CSS-переменные `themeParams` с фолбэками (см. «Design Tokens»).

`Asaka Mini App.dc.html` открывается в браузере напрямую (нужен рядом лежащий `support.js`). Разметка внутри — инлайн-стили; это осознанное ограничение среды прототипирования, в проде используйте нормальные стили/токены.

## Fidelity
**High-fidelity.** Финальные цвета, типографика, отступы, состояния и копирайт (ru). Экраны нарисованы в размере вьюпорта Telegram 390 × 844 pt. UI следует воссоздать с точностью до значений ниже; тексты ru можно брать из макета дословно, uz/en в макете даны только для трёх экранов (Home, чат, карточка продукта) — остальные строки нужно перевести на стороне контента.

## Structure of the prototype file
Документ-прототип состоит из секций (сверху вниз):
1. Обложка — задача и 5 ключевых решений.
2. Дизайн-токены — палитра light/dark, семантика, типошкала, отступы/радиусы/тени, соответствие «эмодзи бота → линейная иконка».
3. Библиотека компонентов — все состояния (default / press / disabled / loading / error).
4. Экраны по флоу A–D (25 экранов) — каждый подписан: главное действие + задействованные нативные элементы Telegram.
5. Три языка — Home / чат / карточка продукта на ru-uz-en (переключатель RU/UZ/EN в шапке документа).
6. Кликабельное демо — 3 сквозных сценария.
7. Заметки для разработки — эндпоинты, асинхронность, платформенные требования.

Переключатель светлой/тёмной темы — в шапке документа; тема применяется как набор CSS-переменных на корневом элементе.

### Демо-режим (сценарии для приёмки)
- **A. «Хочу автокредит»**: Home → квалификация → подбор → калькулятор → результат → заявка → успех (6 тапов после выбора категории; требование брифа — не более 7).
- **B. «Найти ближайшее отделение»**: список → геолокация → карточка → маршрут.
- **C. «Ассистент не помог»**: чат → передача оператору → диалог → оценка 1–5.

## Interactions & Behavior
- **Навигация** — единый стек экранов. `BackButton.show()/hide()` по глубине стека; на корневом экране скрыт, закрытие приложения — только с корня. Собственной кнопки «← Назад» в контенте нет.
- **MainButton** — главное действие каждого экрана, прилипает к низу: активна / disabled (opacity .4 + текст-подсказка, например «Заполните сумму») / loading (`showProgress()`, спиннер, поля блокируются). На экранах-списках и в чате MainButton скрыт.
- **SecondaryButton** — слева от main, outline 1.5 `--brand`, соотношение 1 : 1.3…1.6.
- **Haptics**: `selectionChanged()` — выбор опции, шаг слайдера, звезда рейтинга; `impactOccurred('light')` — нажатие MainButton, тап по карточке продукта; `notificationOccurred('success')` — заявка отправлена, оценка отправлена; `notificationOccurred('error')` — ошибка сети.
- **Клавиатура**: слушаем `viewportChanged`, лента чата и MainButton пересчитываются по `viewportStableHeight`; экран чата не должен ломаться при открытой клавиатуре.
- **Анимации**: `tgpulse` 1.4 s ease-in-out infinite (скелетоны, курсор), `tgtype` 1.1 s с задержками 0 / .15 / .3 s (индикатор набора), `tgspin` .8–1 s linear (спиннеры). Переходы между экранами — стандартные для стека, 200–250 ms ease-out.
- **Валидация**: сумма — форматирование разрядов на лету, границы продукта с мягкой коррекцией (см. экран 16); телефон — формат +998 XX XXX XX XX; имя — не пусто, 2–40 символов; согласие — обязательно для отправки.
- **Ошибки и оффлайн**: сообщения складываются в очередь (CloudStorage) и уходят при восстановлении сети; плашка `--danger-soft` в ленте; повтор отправки заявки — кнопкой, идемпотентность по `client_request_id`.
- **Responsive**: одна колонка, вёрстка тянется по ширине вьюпорта (360–430 pt), высота — по `viewportStableHeight`; safe-area снизу `22px + env(safe-area-inset-bottom)`. Тап-таргеты ≥ 44 pt. Основные действия — в нижней трети экрана.
- **Локализация**: uz-строки на 20–40 % длиннее ru, en — короче. Кнопки и заголовки тянутся по высоте (минимум 2 строки без обрезки), нигде не `white-space: nowrap`, `text-wrap: pretty` для абзацев.

## State Management
Глобально:
- `user` — `{ tgId, firstName, phone?, lang: 'ru'|'uz'|'en' }` (из `initData` + профиль с бэкенда)
- `theme` — из `themeParams` + подписка на `themeChanged`
- `nav` — стек экранов `[{ screen, params }]`
- `chat` — `{ messages[], typing, quickReplies[], mode: 'bot'|'queue'|'operator', queuePosition?, operator?, dailyLimit: { used, max }, outbox[] }`
- `qualify` — `{ productType, answers: Record<stepId, value>, stepIndex, tree }`
- `calc` — `{ productId, amount, term, downPayment, age, rate, monthly, overpay, total, scheduleId }`
- `lead` — `{ name, phone, consent, status: 'idle'|'sending'|'sent'|'error', leadNo? }`
- `branches` — `{ items[], filterType, query, geo?, selectedId }`
- `rates` — `{ items[], updatedAt }`
- `session` — история событий текущей сессии

Ключевые переходы: `bot → queue` (тап «Позвать оператора») → `operator` (`agent_joined`) → `rating` (`agent_left`/пользователь завершил) → `bot`. Таймаут ожидания оператора → системная плашка + возврат в `bot`. Вне 8:00–23:00 переход в `queue` заблокирован, показываем плашку нерабочего времени.

## Data / Endpoints (как в разделе «Заметки для разработки» прототипа)
- **Home**: `initData`; `GET /rates/top?n=3` (кэш 15 мин); `GET /products/categories` (кэш сутки); `GET /branches/nearest` — только после разрешения геолокации.
- **Чат**: WS `/chat` (или SSE) — стрим токенов ответа; `POST /chat/message`; `quick_replies[]` приходят вместе с ответом; богатые карточки — типизированный payload (`product_list`, `calc_result`, `branch_card`, `file`).
- **Квалификация**: `GET /qualify/{product}/tree` один раз, ветвление на клиенте; `POST /qualify/result` → список `product_id`.
- **Калькулятор**: `POST /calc` (сумма, срок, взнос, возраст, product_id), дебаунс 400 мс; ставку считает бэкенд. График: `POST /calc/schedule` (таблица), `GET /calc/schedule.pdf`.
- **Заявка**: `POST /leads { product_id, calc_id, name, phone, client_request_id }` → номер заявки.
- **Отделения**: `GET /branches?type=&q=&lat=&lon=`, пагинация по 20; статичный map-тайл отдаёт бэкенд.
- **Оператор**: WS-события `queue_position`, `agent_joined`, `agent_left`, `timeout`, `out_of_hours`; `POST /operator/rating`.
- **Асинхронность**: курсы и каталог — stale-while-revalidate из кэша; ответ ассистента > 800 мс → индикатор набора, > 3 с → скелетон-пузырь; поиск отделений — дебаунс 300 мс, минимум 2 символа.
